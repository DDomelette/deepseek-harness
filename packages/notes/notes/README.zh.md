# @deepseek-ai/dsh-notes

[English](README.md) | 中文

## 概述

`dsh-notes` 留存用户想要回看的素材。从 dsh 会话里收集的一段文字或一张截图成为一条笔记；配置好的模型在各自的会话中作答，因此笔记的提问与追问不会落到素材来源的那个会话里。一个包同时承载两个半边：宿主半边拥有笔记存储域、笔记设置节、笔记会话与 `notes` Remote 命名空间；浏览器半边拥有右列的笔记页签，以及打开它的对话标题栏控件。

## 使用本包

当 Web 部署需要把会话素材留存为逐条作答的笔记时使用本包。把它挂载在已经提供存储 hub 域设施的组装里；插件自己打开名为 `notes` 的域，不需要额外的存储行。

### 组合

```yaml
- id: notes
  name: '@deepseek-ai/dsh-notes'
```

裸行不需要 `config`：schema 把策略默认为 `manual`，把动作列表默认成内置的 `translate` 动作。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `strategy` | `manual` | `manual` 等待显式分析；`auto` 在素材收集时立即分析。 |
| `actions` | 一个 `translate` 功能 | 划词浮层提供的划词功能。 |
| `actions[].id` | — | 稳定的功能 id，作为素材自己的 `action` 存储。 |
| `actions[].label` | — | 浮层显示的本地位文案。 |
| `actions[].prompt` | — | 提交前前置到素材正文的提示词。 |
| `actions[].autoSend` | `false` | 点选该功能是否立即分析，不受策略影响。 |
| `workspace` | 缺省 | 笔记会话运行的绝对目录，来自设置卡或组装入口。 |
| `model` | 缺省 | 笔记会话的模型覆盖；缺省则沿用会话默认。 |
| `model.provider` | — | 已注册的 provider 路由。 |
| `model.model` | — | provider 拥有的模型 id。 |
| `model.reasoningEffort` | 缺省 | 该路由的适配器推理等级；缺省则用路由自己的默认值。 |

### 宿主服务

插件挂载六个服务，每个服务是它那一部分契约的文档归属。`ctx.notesStore` 打开笔记域并持有素材表与会话表；`ctx.notesMaterials` 存储素材、手工顺序与归档区；`ctx.notesSessions` 按配置的工作区与模型启动会话、为每个会话记录一条条目，并持有面板的活动指针；`ctx.notesSettings` 读取上面的设置节，在没有挂载设置 provider 时回落到组装入口的值；`ctx.notesAnalysis` 把一条素材变成它所在会话上的一条用户消息；`ctx.notes` 是浏览器面板调用的 Remote 命名空间，它的操作以 `src/types.ts` 里的 wire 词汇作答——成功值或具名拒绝——因此没有任何东西以抛出异常的形式到达面板。

### 浏览器半边

浏览器半边向 `ctx.sidebarRightTabs` 注册一个页面类型——kind 为 `notes`，按名字打开、不识别任何资源地址——并从 keyed 座位 `sidebar.right.pane.tab` 绘制它。面板在窗格够宽时并排显示两栏——素材列表与打开素材的详情——低于 560px 时一次只显示一栏，由读者在两栏之间移动；低于 500px 时导航栏收起控件文字，只留图标。列表行带状态、来源、两行正文，以及产生它的收集动作标签，其下是可展开的「已归档」区。素材正文在进入会话前可编辑，追问输入框则在进入会话后才绘制，与宿主的强制规则一致；「分析」控件只在素材仍是草稿时绘制，而刷新控件会重读会话列表、当前会话的素材，以及已打开素材的线程。详情另外回显该素材所命名的动作的提示词模板，并提供复制当前所显示正文的按钮。导航栏里的会话胶囊列出全部会话（含已归档），选中已归档的那条会把它取回；它旁边的控件分别启动新会话、归档当前会话、重新读取全部内容、在停靠与浮窗两种呈现之间切换、添加截图，并打开覆盖在笔记设置节之上的设置卡。对话标题栏角落座位上的控件打开该页签；再次打开只会显示已存在的那一个，而不会新增第二个。浏览器半边也覆盖会话本身：选中段落上方的气泡提供该部署的收集动作，点选其中一个就把段落存进当前显示的会话——没有会话时先启动第一个。从面板导航栏选中的截图，或在面板内任意位置粘贴的截图，以同样方式存储，成为一条正文是持久附件引用而不是字节的素材；粘贴监听挂在面板上，因此在对话输入框里的粘贴仍然是发给模型的附件。面板与气泡共用同一个 store 实例而不是各自一个，因此在会话上收集的段落会落进面板正在渲染的状态；两者都只通过 `ctx.remote.notes` 读写，因此都不持有任何宿主不会执行的规则。

### 设置

设置卡编辑的正是组装入口播种的那个设置节：模型调用策略、工作区、模型覆盖，以及每条划词功能的名称与提示词。它通过 `notes/settingsUpdate` 一次写一个字段，而写入是"取消该字段"而不是存下 null，因此清空工作区或模型覆盖会把该字段交还给组装默认值。功能列表是"一次一个字段"的例外：卡片发送的是把被编辑功能替换掉的**完整列表**，因为列表本身就是一个文档值。若某条功能的 id、标签或提示词为空白，或有两条功能共用同一个 id，宿主会拒绝并回报 `invalid-actions`；卡片在字段为空白时也不提供保存。

目录字段右侧带一个选择按钮，通过 wire 向宿主取一个目录：部署提供原生选择器时打开它，只提供 browse 原语的部署则在卡片内展开一个浏览器——当前层级、它的子目录，以及进入、上一级、使用此目录与取消四个控件；盘符根之上再上一级就是宿主报告的卷列表。取消选择器或浏览器都不改动输入框；宿主读不到某一层时报告 `directory-unavailable`。

模型选择器列出该部署自己的 catalog 所提供的路由，按 provider 分组，读的是对话模型选择器用的同一个 session 操作；每条路由声明的推理等级作为第二个选择器出现；设置节仍存着某条路由而 catalog 已不再列出它时，它依旧可选。划词功能选择器列出已配置的功能，旁边的编辑器可以改名或新增：新增的功能拿到下一个空闲的 `custom-N` id，名称为空或提示词为空会被拒绝，「+」单独占选择器下方一行。没有可写设置 provider 的部署会如实说明，而不是照样给出控件。

### 预期行为

素材先存储、后提交，因此收集过程从不为模型阻塞。新建会话会在尚无记录时把配置的目录登记为标题「笔记」的工作区，把该会话作为已记账的 Session 加入其中，并同时在笔记记录与该 Session 上写下「笔记 · NN」——笔记前缀加上域内记录数的两位数字（含已归档）——因此读者的会话列表会把笔记会话归到一组，并逐行显示标题，而不是用目录名代替。分析与追问都对素材自己的笔记会话调用 `Agent.followup()`——绝不对素材来源的会话调用——每次提交各占一个 step，所以两条素材必然产生两个回答。提交后的素材在承载它的那个 turn 结束之前一直是 `analyzing`：模型作答使它变成 `analyzed`，turn 失败或被中止则使它变成 `failed` 并记下原因——因此面板显示的状态是模型的真实结果，而不是猜测。inbox 拒绝发送时会立刻把素材标记为 `failed` 并回滚已记录的消息 id，因此该素材仍可再次分析；宿主把这次拒绝回报为带原因的 `submit-refused`，而不是"无法连接到宿主"；在收集时即提交的部署会用这次拒绝代替那个素材 id。同一素材的两次分析若相互竞争，只会发送一次：先到者在域的写链上认领该素材，后到者看到已记录的 id 便不再提交。铸造素材顺序值的操作出于同样原因串行化，因此新素材总是落在上一条之上。处于最后一个未归档位置的会话不可归档，因此面板永远有一个会话可显示。截图与其他素材一样被提交，形式是点名其存储返回的那份引用的 image block，它在会话线程里的那一行也会说明自己带着图片；模型声明只接受文字输入的会话会回报 `image-unsupported` 而不是把它发出去；对尚未进入会话的素材追问会回报 `material-not-submitted`。截图素材的正文就是那份引用，因此详情面板只标出它而不提供编辑器；若仍有调用方要求改写，`materialUpdate` 会回报 `material-not-text`。

## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

本节说明宿主半边如何接线；可观察的行为见[使用本包](#use-this-package)。

### 存储

会话日志是内容真相。插件自己的域只存日志回答不了的东西：有哪些素材、它们的手工顺序、提交过哪些用户消息，以及面板当前显示哪个会话。素材正文与模型回答都从会话事件读回，绝不复制到这里。`ctx.storageDomain.open` 对同一个域名只允许一次打开，因此由一个所有者（`ctx.notesStore`）打开域，并把它的表交给其余每个消费者。

### 提交

`src/analysis.ts` 组装内容、用 `createUserMessage` 造出用户消息、记录消息 id，**然后**才调用 `followup`。内容由 `src/compose.ts` 决定：文字素材贡献一个 text block，动作模板前置在正文之前；截图贡献点名素材所存引用的 image block，该模板作为 text block 排在它前面。这个顺序是刻意的：`Agent.followup()` 返回 void，消息落进日志的 seq 在调用点不可知，而它的 id 在发送前就可知。发送被拒时回滚该 id——否则素材会被读成"已提交"，永远无法重试。

一次提交的结果由承载它的那个 turn 落定。日志发布 `turn/end` 时，`src/turns.ts` 从会话日志里把该 turn 读回来——它带的是哪几条用户消息、模型是否作答——`Analysis` 再把仍然处于 `analyzing` 的自己名下的素材推进到 `analyzed` 或 `failed`。来源是日志而不是内存，因此被恢复的会话也按同样方式落定。

### 线程归属

`src/thread.ts` 回答哪些会话事件属于一条素材。归属是显式的，绝不按位置划分：素材记录自己每条用户消息的 id，每条这样的消息纳入它之后、下一条对话收到的 prompt 之前的全部事件。因此在首次分析很久之后、且在其他素材已被分析之后提出的追问，仍然落在正确的线程里。harness 自己的上下文——工作区说明、系统提示词快照、技能目录——在同一个 turn 内同样以 user 消息落进日志，因此由线段透明携带、不画成任何一行；所谓 prompt，就是那条不声明 context form 的 user 消息，无论发送者是人还是插件。

</details>

<a id="model-experience"></a>
## 模型体验

### 素材提交

#### 模型看到什么

每次分析或追问产生一条 `user/message`，落在该素材自己的笔记会话上。文字素材提交它的文字；通过动作收集的素材会把该动作配置的提示词模板单独一行前置，截图素材则在图片之前前置该模板。截图提交的是点名其存储返回的那份持久引用的 image block，因此模型读到的就是图片本身。消息来源是 `{ kind: 'plugin', plugin: 'notes' }`，因此轨迹把它归属到本插件而不是用户。路由若声明只接受文字输入，提交会在发出任何东西之前被拒绝（`image-unsupported`），因此模型永远不会收到替代截图的那段占位文本。

#### Token 影响

提交的正文，加上笔记会话常规的逐条消息包装。素材处于 draft 时什么都不发送；动作模板属于配置，因此部署改变它的长度不需要改代码。

#### KV Cache 影响

对派生的请求前缀没有影响。每次提交只追加到它自己会话的历史上，因此笔记会话像其他任何会话一样增长，其他会话的前缀不变。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制说明本包在什么情况下不合适，或需要特别的运维注意。它们是当前约束，不是任务清单。

- **一条素材只分析一次** —— 只有素材仍是草稿时详情才提供「分析」，因为宿主对一条素材的第一条消息至多提交一次。turn 失败的素材会保留已记录的消息，因此它只报告失败而无法再次提交；只有被 inbox 拒绝的发送会回滚 id 并保持可分析。
- **收集到的段落记录了来源，但目前还不能打开它** —— 浮层从选区起始所在的那一行 DOM 读取 `seq`、`messageId` 与 `callId`，只要记录了其中任意一项，来源条就会给出「定位原文 ↗」入口；点击后它会说明本版无法打开原文，因为对话的公开面没有为槽树之外的面板提供视图导航。从面板自己的控件收集来的素材没有对应的行，因此根本不渲染该入口。
- **截图来自面板，而不是会话** —— `notes/materialAddImage` 存下附件存储返回的引用，并把该引用作为 image block 提交；面板的图片来源是自己的选择器或面板内的粘贴（一次粘贴收一张），而没有任何路径截取会话本身的区域，在对话输入框里的粘贴仍然是发给模型的附件。
- **声明只接受文字输入的路由会拒绝截图** —— 由该会话的模型元数据决定：明确声明只接受文字时报 `image-unsupported`，面板提示换一个模型；模态未知的路由按"有图片能力"处理，交由请求组装决定。
- **笔记会话必须是活的** —— `analyse` 与 `ask` 通过 `ctx.agents` 解析活的 Agent，因此进程重启过的会话会回报 `session-not-live`，直到它被重新打开；而 turn 从未闭合（进程在 turn 中途停止）的素材会停在 `analyzing`，因为只有闭合的 turn 才会落定素材。
- **进入会话的素材不可再编辑** —— 素材一旦记录了消息，`materialUpdate` 就回报 `material-submitted`：提交的正文由会话日志承载，改写记录会让列表行与它的线程脱节。
- **孤儿附件永不回收** —— draft 状态下删除的素材会留下已上传的字节，与附件面既有语义一致。
- **会话按创建顺序恢复** —— 取出的会话回到它的创建位置而不是列表顶部，因为记录没有单独的顺序值。
- **创建会话需要先配置工作区** —— 在笔记工作区设定之前启动会话会回报 `workspace-missing`；本阶段没有首次启用引导界面，工作区来自设置文档或组装入口。
- **会话在创建时才加入笔记工作区** —— 插件在创建时登记配置的目录，并把新 Session 记到它名下；因此在目录被登记之前记录的会话会保持它原有的位置（目录名，落在未分组标题下），不会被追溯收养。
- **本插件写下的名字是中文常量** —— 新会话的标题 `笔记 · NN` 与本插件自行登记的目录名「笔记」都在宿主侧写下，此时还不存在任何读者语言环境，因此它们不是由语言环境拥有的文案。读者此前已登记的目录保留他们自己起的名字；之后在会话列表里重命名该 Session 只改变那一行，不会改变面板自己的会话胶囊。
