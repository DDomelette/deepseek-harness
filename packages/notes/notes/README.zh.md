# @deepseek-ai/dsh-notes

[English](README.md) | 中文

## 概述

`dsh-notes` 留存用户想要回看的素材。从 dsh 会话里收集的一段文字或一张截图成为一条笔记；配置好的模型在各自的会话中作答，因此笔记的提问与追问不会落到素材来源的那个会话里。一个包同时承载两个半边：宿主半边拥有笔记存储域、笔记设置节、笔记会话与 `notes` Remote 命名空间；浏览器半边拥有右列的笔记页签，以及打开它的对话标题栏控件。

<a id="use-this-package"></a>
## 使用本包

当 Web 部署需要把会话素材留存为逐条作答的笔记时使用本包。把它挂载在已经提供存储 hub 域设施的组装里；插件自己打开名为 `notes` 的域，不需要额外的存储行。

### 组合

```yaml
- id: notes
  name: '@deepseek-ai/dsh-notes'
```

裸行不需要 `config`：schema 把策略默认为 `manual`，把动作列表默认成内置的 `translate` 动作。

### 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `strategy` | `manual` | `manual` 等待显式分析；`auto` 在素材收集时立即分析。 |
| `actions` | 一个 `translate` 动作 | 划词浮层提供的收集动作。 |
| `actions[].id` | — | 稳定的动作 id，作为素材自己的 `action` 存储。 |
| `actions[].label` | — | 浮层显示的本地位文案。 |
| `actions[].prompt` | — | 提交前前置到素材正文的提示词。 |
| `actions[].autoSend` | `false` | 点选该动作是否立即分析，不受策略影响。 |
| `workspace` | 缺省 | 笔记会话使用的绝对工作区路径，首次启用时选定。 |
| `model` | 缺省 | 笔记会话的模型覆盖；缺省则沿用会话默认。 |
| `model.provider` | — | 已注册的 provider 路由。 |
| `model.model` | — | provider 拥有的模型 id。 |

### 宿主服务

插件挂载六个服务，每个服务是它那一部分契约的文档归属。`ctx.notesStore` 打开笔记域并持有素材表与会话表；`ctx.notesMaterials` 存储素材、手工顺序与归档区；`ctx.notesSessions` 按配置的工作区与模型启动会话、为每个会话记录一条条目，并持有面板的活动指针；`ctx.notesSettings` 读取上面的设置节，在没有挂载设置 provider 时回落到组装入口的值；`ctx.notesAnalysis` 把一条素材变成它所在会话上的一条用户消息；`ctx.notes` 是浏览器面板调用的 Remote 命名空间，它的操作以 `src/types.ts` 里的 wire 词汇作答——成功值或具名拒绝——因此没有任何东西以抛出异常的形式到达面板。

### 浏览器半边

浏览器半边向 `ctx.sidebarRightTabs` 注册一个页面类型——kind 为 `notes`，按名字打开、不识别任何资源地址——并从 keyed 座位 `sidebar.right.pane.tab` 绘制它。面板在窗格够宽时并排显示两栏——素材列表与打开素材的详情——低于 560px 时一次只显示一栏，由读者在两栏之间移动；低于 500px 时导航栏收起控件文字，只留图标。列表行带状态、来源、两行正文，以及产生它的收集动作标签，其下是可展开的「已归档」区。素材正文在进入会话前可编辑，追问输入框则在进入会话后才绘制，与宿主的强制规则一致；详情另外回显该素材所命名的动作的提示词模板，并提供复制当前所显示正文的按钮。导航栏里的会话胶囊列出全部会话（含已归档），选中已归档的那条会把它取回；它旁边的控件分别启动新会话、归档当前会话、重新读取全部内容、在停靠与浮窗两种呈现之间切换、添加截图，并打开覆盖在笔记设置节之上的设置卡。对话标题栏角落座位上的控件打开该页签；再次打开只会显示已存在的那一个，而不会新增第二个。浏览器半边也覆盖会话本身：选中段落上方的气泡提供该部署的收集动作，点选其中一个就把段落存进当前显示的会话——没有会话时先启动第一个。从面板导航栏选中的截图以同样方式存储，成为一条正文是持久附件引用而不是字节的素材。面板与气泡都只通过 `ctx.remote.notes` 读写，因此两者都不持有任何宿主不会执行的规则。

### 设置

设置卡编辑的正是组装入口播种的那个设置节：模型调用策略、工作区与模型覆盖。它通过 `notes/settingsUpdate` 一次写一个字段，而写入是"取消该字段"而不是存下 null，因此清空工作区或模型覆盖会把该字段交还给组装默认值。收集动作以只读方式列出；编辑一组提示词模板需要这张卡目前还没有的表单。没有可写设置 provider 的部署会如实说明，而不是照样给出控件。

### 预期行为

素材先存储、后提交，因此收集过程从不为模型阻塞。分析与追问都对素材自己的笔记会话调用 `Agent.followup()`——绝不对素材来源的会话调用——每次提交各占一个 step，所以两条素材必然产生两个回答。inbox 拒绝发送时，素材被标记为 `failed` 并保留原因，同时回滚已记录的消息 id，因此该素材仍可再次分析。同一素材的两次分析若相互竞争，只会发送一次：先到者在域的写链上认领该素材，后到者看到已记录的 id 便不再提交。铸造素材顺序值的操作出于同样原因串行化，因此新素材总是落在上一条之上。处于最后一个未归档位置的会话不可归档，因此面板永远有一个会话可显示。截图会被收集并列出，但不会被提交：没有任何路径把它存下的附件引用组装成模型请求，因此分析会回报 `image-not-submittable`，而不是发出一条没有指名任何素材的请求；对尚未进入会话的素材追问会回报 `material-not-submitted`。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

本节说明宿主半边如何接线；可观察的行为见[使用本包](#use-this-package)。

### 存储

会话日志是内容真相。插件自己的域只存日志回答不了的东西：有哪些素材、它们的手工顺序、提交过哪些用户消息，以及面板当前显示哪个会话。素材正文与模型回答都从会话事件读回，绝不复制到这里。`ctx.storageDomain.open` 对同一个域名只允许一次打开，因此由一个所有者（`ctx.notesStore`）打开域，并把它的表交给其余每个消费者。

### 提交

`src/analysis.ts` 组装正文、用 `createUserMessage` 造出用户消息、记录消息 id，**然后**才调用 `followup`。这个顺序是刻意的：`Agent.followup()` 返回 void，消息落进日志的 seq 在调用点不可知，而它的 id 在发送前就可知。发送被拒时回滚该 id——否则素材会被读成"已提交"，永远无法重试。

### 线程归属

`src/thread.ts` 回答哪些会话事件属于一条素材。归属是显式的，绝不按位置划分：素材记录自己每条用户消息的 id，每条这样的消息纳入它之后、下一条用户消息之前的全部事件。因此在首次分析很久之后、且在其他素材已被分析之后提出的追问，仍然落在正确的线程里。

</details>

<a id="model-experience"></a>
## 模型体验

### 素材提交

#### 模型看到什么

每次分析或追问产生一条 `user/message`，落在该素材自己的笔记会话上。正文是素材的文字；通过动作收集的素材会把该动作配置的提示词模板单独一行前置。消息来源是 `{ kind: 'plugin', plugin: 'notes' }`，因此轨迹把它归属到本插件而不是用户。只有文字素材会到达模型：截图存下的是持久附件引用，而目前没有任何路径把该引用解析成 image content part。

#### Token 影响

提交的正文，加上笔记会话常规的逐条消息包装。素材处于 draft 时什么都不发送；动作模板属于配置，因此部署改变它的长度不需要改代码。

#### KV Cache 影响

对派生的请求前缀没有影响。每次提交只追加到它自己会话的历史上，因此笔记会话像其他任何会话一样增长，其他会话的前缀不变。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制说明本包在什么情况下不合适，或需要特别的运维注意。它们是当前约束，不是任务清单。

- **收集到的段落不带消息身份** —— 浮层从会话 DOM 里读取选区，而 DOM 没有标记它来自哪条消息，因此素材不记录 `seq`、`messageId` 或 `callId`，暂缓的"定位原文"入口目前也无处可指。
- **截图会被收集，但不会被提交** —— `notes/materialAddImage` 只保留附件存储返回的引用，而目前没有任何路径把该引用解析成 image content part，因此分析会回报 `image-not-submittable`；也没有任何路径截取会话本身的区域。
- **笔记会话必须是活的** —— `analyse` 与 `ask` 通过 `ctx.agents` 解析活的 Agent，因此进程重启过的会话会回报 `session-not-live`，直到它被重新打开。
- **进入会话的素材不可再编辑** —— 素材一旦记录了消息，`materialUpdate` 就回报 `material-submitted`：提交的正文由会话日志承载，改写记录会让列表行与它的线程脱节。
- **孤儿附件永不回收** —— draft 状态下删除的素材会留下已上传的字节，与附件面既有语义一致。
- **会话按创建顺序恢复** —— 取出的会话回到它的创建位置而不是列表顶部，因为记录没有单独的顺序值。
- **创建会话需要先配置工作区** —— 在笔记工作区设定之前启动会话会回报 `workspace-missing`；本阶段没有首次启用引导界面，工作区来自设置文档或组装入口。
