# Agent Note: 上游 0.2.2 与分支自有功能的集成

Status: implemented

[English](2026-11-08-upstream-022-fork-integration.md) | 中文

## 问题

本分支的手机配对、置顶排序、笔记、技能设置、递归删除会话和 E2B 提供者依赖上游 0.2.2 已替换的 API。此前的上游集成复制了发布版本的文件树，却没有将上游记录为合并父提交，因此仅凭 Git 祖先关系无法确定内容基线。再次导入快照会加重这种歧义，并让共享 API 的消费者停留在不兼容的版本。

## 决策

集成使用 [0.2.1 集成](2026-10-12-upstream-merge-integration.zh.md) 确定的内容基线进行三方协调，并将上游发布版本记录为合并父提交。当前包位置、应用组装、工具执行接口、远程服务和构建工具由上游实现主导。本分支的自有功能使用这些 API；重复的包位置和被替代的 MCP 监督器不再存在。

浏览器启动 Cookie 保持版本 1，配对设备 Cookie 保持版本 2。API 连接 Cookie 使用版本 3，因为上游的版本 2 会与已持久化的设备凭据冲突。每个配对设备拥有自己的 Peer 生命周期，因此撤销设备会结束其连接，而不销毁浏览器操作者。设备管理还要求调用者来自回环地址。HTTP resource 适配器向浏览器认证传递套接字地址，为 Fetch 请求保留回环依据。可信局域网中未经鉴权的请求会收到状态码为 HTTP 401 的配对页面；在大小写不敏感的文件系统上，索引别名与配置的索引文件接受相同的鉴权处理。

MCP 设置面板读取当前 Manager 与加载器声明条目的精简 `mcpServers` 投影，投影中不包含凭据。面板写入 `mcp-manager` 条目，旧设置导入将 `mcp-servers` 映射到该条目。声明式服务器名称不能与配置中的名称冲突。Manager 拥有连接生命周期，其状态通知会隔离失败的观察者。Manager 不发布重复自身配置验证的不变量伴随模块。团队状态同样只有一个已提交的投影，而不使用伴随模块重复执行相同的折叠。

笔记、置顶、删除和技能目录端点在共享查看器的端点分类中明确只对所有者开放。工作区跟随响应将本分支的归档时间与标记限制在可见的会话集合内。Remote 组装和笔记的两个编译面引用同一个仅生成声明的笔记类型项目。投影观察者抛出的错误不能阻止其他观察者。E2B 使用共享补丁库和按目标顺序获取的锁，实现当前带条件保护的补丁、删除和移动操作；若移动已发布目标文件却无法删除源文件，会报告这一部分完成的结果。

本分支保留手机端浮动入口和边缘滑动抽屉，同时让折叠屏横向姿态参与当前列宽计算。界面测试区分本地交互状态和宿主拥有的置顶顺序：拖动置顶项写入置顶领域，不改变会话手动排序。

已提交的会话代际文件和已封存的 Agent Note 三件套保持原有字节。新的上游产物以新增文件保留。运行时删除操作针对用户拥有的会话存储，不针对已提交的测试数据历史。

分支工作流选择公开的 GitHub 托管运行器。拉取请求的覆盖率、兼容性、构建产物和基准测试作业使用 Ubuntu 26.04。自动运行真实 API 端到端测试要求设置 `DSH_RUN_REAL_API_E2E=true`；明确手动运行仍要求凭据，缺少凭据时预检会失败。上游保留自动端到端测试和自身的运行器路由。仓库所有权检查使用 GitHub 返回的规范上游标识，外部 Action 仓库名称保留各自的标识。

## 考虑过的替代方案

**用上游文件树替换整个分支。** 这会移除已支持的配对、笔记、置顶与提供者行为，因此集成选择迁移它们的消费者。

**在 Manager 旁保留旧 MCP 运行时。** 两个所有者会同时协调相同的配置服务器，并在生命周期与设置上产生分歧。因此面板改为投影 Manager。

**复用上游的 API Cookie 版本。** 版本 2 已标识本分支的设备 Cookie；区分载荷版本可以保留现有设备，并防止不同凭据类型相互通过鉴权。

**再次导入只有一个父提交的快照。** 这会重复祖先关系缺失的问题，使后续协调仍依赖重建另一份内容基线。

## 影响

后续上游合并具有已记录的祖先关系。本分支仍负责额外 API 与界面行为的集成工作。共享测试遵循当前接口，分支回归测试覆盖鉴权、设备生命周期、投影观察者、E2B 操作、置顶排序与设置投影。源码模式下的不变量导入解析到源码伴随模块，构建后的消费者继续使用已发布导出。需要创建文件符号链接的 Windows 测试要求宿主具备对应权限。
