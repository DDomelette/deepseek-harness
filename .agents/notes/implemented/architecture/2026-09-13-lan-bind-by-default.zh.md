# Agent Note: dsh web 默认绑定所有网卡

Status: implemented

[English](2026-09-13-lan-bind-by-default.md) | 中文

## 问题

从手机访问 Web GUI 需要 Host 监听局域网，而过去每次启动都要敲 `dsh web --host 0.0.0.0 --allow-lan`：组合后的 host 默认是 `127.0.0.1`，而显式写出全接口 host 却不带确认旗标属于用法错误。这份部署每天都会从终端多次启动 GUI，而「连接手机」入口之所以一直报 `mob/loopback-only` 并提示敲这两个旗标，唯一原因就是它们。[LAN Web 服务](2026-09-11-lan-web-serving.zh.md)拥有栅栏、警告与那个确认的来龙去脉；[手机接入归入 web profile](2026-09-12-phone-access-in-the-web-profile.zh.md)拥有该入口本身。

## 决策

调用未指定 host 时，`dsh web` 绑定 `0.0.0.0`。web profile 的 webserver 行部署回退值改为 `0.0.0.0`，因此裸敲 `dsh web` 就会服务局域网：就绪行打印不带令牌的局域网 URL，「连接手机」入口保持可用。

`--host 127.0.0.1` 是退出口：只绑定回环、不打印局域网行，并让配对入口报告内网访问未开启（`mob/loopback-only`）。`--allow-lan` 仍被接受并记录为冗余，因此按旧默认写下的命令仍可运行。

其余规则一律不变：启动令牌仍只在回环 authority 上交换，局域网浏览器仍用它配对所得的设备 cookie 认证，Host/Origin 栅栏仍决定哪些 authority 受信，绑定所有网卡时挂载期仍打印明文 HTTP 警告。

## 曾考虑的替代方案

- **保留确认旗标。** 对这份部署否决：操作者在选择把 GUI 提供给家庭网络时就已经接受了局域网暴露，而每次启动都重复确认只会让手机入口读起来像坏了，而不是像被保护着。
- **profile 级的一次性同意。** 否决，因为这里没有人需要这一步：为了一个这份部署从不省略的旗标，它要多加一个配置字段、第二个决定点，以及一个「内网为什么没开」的失败模式。
- **用 shell 别名代替产品默认。** 否决：它把选择藏进某位操作者的 shell 配置，于是其他每一次调用——脚本、第二个检出、打包安装——都仍是回环默认，手机入口也一直报未开启。

## 后果

- [LAN Web 服务](2026-09-11-lan-web-serving.zh.md)仍是绑定、栅栏与明文 HTTP 警告的权威；它的确认旗标如今是冗余形式，而不再是被要求的形式。
- [手机接入归入 web profile](2026-09-12-phone-access-in-the-web-profile.zh.md)曾把「让全接口绑定成为 `dsh web` 的默认」记为否决；本笔记采纳了那个替代方案。
- 暴露成为初始状态：这台机器上任何 `dsh web` 都以明文 HTTP 服务局域网，挂载期警告是唯一的提示。`--host 127.0.0.1` 是记录在案的退路，操作者采用它时配对入口会点名该旗标。
- 这是部署本地默认，因此与被链接的两份笔记所记录的上游决策分叉；想要回确认的部署传 `--host 127.0.0.1` 即可。
