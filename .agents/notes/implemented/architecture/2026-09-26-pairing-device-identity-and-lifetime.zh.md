# Agent Note：配对设备身份、改名与一天默认寿命

Status: implemented

[English](2026-09-26-pairing-device-identity-and-lifetime.md) | 中文

## 问题

配对面板把每台批准的手机登记在从其 `User-Agent` 推导的名称下，之后无法改名，也没有硬件指纹，两台同型号手机无法区分。每台设备的寿命界面是一行预设档位加一个独立的任意天数输入框，且新配对的设备会静默得到三十天的凭证窗口。

## 决策

- **经 ARP 的 MAC 指纹。** 批准路由从 `PairingSessions.sourceOf` 读取领取手机的远端地址——在必经的配对页领取时与 agent 一并记录——并通过系统 ARP 表解析（Windows 用 `arp -a`，其他平台用 `arp -n`）。手机刚与 Host 通信过，因此条目是新鲜的；条目缺失或过期、来源不是 IPv4、或平台没有 `arp` 时，不记录 MAC 而不是让批准失败。解析到的 MAC 归一化为小写冒号形式，并在登记表的持久化记录边界按该形态校验。
- **改名。** `renameDevice` 通过与其它登记表变更相同的读-改-写路径为活动或回收站中的条目改名，对外暴露为 `POST /pair/devices/label`（非空、至多 64 字符，同样的回环加会话守卫），设备行上是内联的改名输入框。
- **凭证有效期下拉菜单。** 面板把预设档位与任意天数输入框收拢为一个「凭证有效期」菜单——1/7/30/90 天档位，底部固定的「自定义…」展开天数行。
- **一天默认值。** `deviceLifetimeDays` 默认为 1，操作者不再过问的配对在第二天即过期，而不是一个月后；1–365 的范围不变。

## 考虑过但未采用的方案

- **以 MAC 作为设备 id。** 否决：ARP 解析是尽力而为的（经过路由或 VPN 的路径没有条目），MAC 只能作为条目的装饰；随机 `PairedDeviceId` 仍是身份。
- **从请求头或 TLS 做被动指纹。** 否决：局域网 HTTP 路径上不暴露稳定的硬件标识，自行编造会把共享设备标错。

## 影响

- 只有当领取经 IPv4 到达本地链路时，设备行才能显示 MAC 行；回环的测试领取与跨子网的手机不显示。
- [配对请求需有手机领取](2026-09-26-pairing-requests-require-claim.zh.md)仍是「短码何时进入待决列表」的权威；本笔记只拥有登记行记录什么，凭证到期时间除外，它由[续期与记录](../bug-fix/2026-10-06-device-credential-truth-and-renewal.zh.md)拥有。
