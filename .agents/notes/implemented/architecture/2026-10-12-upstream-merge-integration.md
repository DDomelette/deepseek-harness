# Agent Note: Upstream 0.2.1-alpha.2 merge integration decisions

Status: implemented

English | [中文](2026-10-12-upstream-merge-integration.zh.md)

## Problem

The fork merged upstream 0.2.1-alpha.2 (`upstream/master` `d743267388`) into a tree that had diverged across the session family, the shells, the subagent plane, the settings plane, and the job mirror. Upstream had replaced several seams the fork's features were built on — the jobs notification API, the settings provider seam, `SubagentRuntime`'s continuation entry points, the message-source vocabulary, the session log format — and had also shipped surfaces this fork has no consumer for. Each seam needed a decision: port the fork's behaviour onto the new API, take upstream's replacement and delete the fork's, or shelve the upstream surface. Adopting upstream's `SESSION_FORMAT_VERSION = 4` while the JSONL scanner still admitted current-generation rows with the V3 rule left every session log containing a system message unreadable, which surfaced first as nine cold-resume failures in the Agent Team package.

## Decision

Port the fork's behaviour onto the merged APIs, keep fork-only implementation inside packages where the fork's code is the surviving implementation, and shelve upstream surfaces that nothing in this tree mounts. The sections below record the four ports that shaped shipped behaviour, the settings and session-format moves, and what was deliberately not taken.

## The Loader is upstream's, and fail-loud moves to the startup audit

Upstream's `packages/boot/**` is adopted byte-for-byte, and it audits a settled tree: `mountRootInclude()` returns, `inactiveEntries()` walks `ctx.loader.entries()`, and `auditStartupEntries()` turns an inactive required row into `StartupError`. The fork's vendored `vendor/{loader,include}` instead made configuration reload transactional — `EntryGroup.update()` threw the first child failure — so boot never reached the audit and every failing row surfaced as `plugin tree failed to load: failed to apply loader entry include (cordis:include): …` rather than `startup failed: 1 required plugin did not activate`. Thirty-seven boot cases failed on that mismatch alone. The vendored loader now carries upstream's lifecycle: `entry.ts`, `group.ts` and `tree.ts` are upstream's, `group.ts` catches each child's `create()` failure and logs it, and a row whose import fails stays attached with no fiber. "Misconfiguration fails loud at load" is relocated, not dropped: the Loader names the row it could not start, and the boot audit is what refuses the launch. Both halves are pinned by `packages/boot/app-boot/tests/app-boot.spec.ts`.

The fork keeps the vendor additions upstream does not provide, each recorded in `vendor/README.md`: the durable debounced include writes, the serialized per-Include write queue — now drained before the root stops, so a rejected write still rejects teardown — the lazy `internal/config` resolution, `disabled` interpolation, `moduleNamespace`, and the volatile configuration branch. The two fork host specs that pinned the transactional loader are re-expressed on the audit behaviour rather than deleted: `packages/host/webserver/tests/webserver.spec.ts` settles the webserver fiber as failed and asserts its `fiber.await()` rejects with `EADDRINUSE`, and `packages/host/directory-picker-auto/tests/loader-composition.spec.ts` asserts the failed surface row holds no fiber while its sibling stays mounted and the import failure reaches the loader's error channel.

## Job changes ride the merged jobs event stream

The fork's `SessionControlController` mirrored background jobs per session and `ui-jobs` rendered its header over that mirror, so deleting the wiring the way upstream does would have removed a live feature. The merged jobs service replaced `onJobsChanged(owner)` with a filtered event stream, so `packages/api/session-controller/src/control.ts` subscribes with `events.subscribe({ owners: 'all' }, …)`, ignores the `output` and `progress` events that move no published row, and republishes on the lifecycle commits that map onto the old notification sites. Job lookups pass a `SessionId` (`jobs.list(caller)`), not an `Agent`, matching the merged registry: an unowned job is visible to every caller, and a job with an owner is visible to that session.

## The subprocess control channel is an additive port

The fork's reliability work needed a byte channel beside stdio. `packages/subprocess/subprocess/src/control.ts` owns the protocol: descriptor `SUBPROCESS_CONTROL_FD` 7, the private launch marker `DSH_SUBPROCESS_CONTROL`, and `openInheritedControlChannel()`, which consumes the marker and returns a byte-mode duplex socket over the inherited descriptor. `SubprocessStdio` gains the optional `control?: 'pipe'` request and `SubprocessHandle` gains the optional `control` duplex, so a launcher that does not ask for the channel is unaffected. The Windows launch path carries the same channel through `packages/subprocess/win32-process/src/control-stdio.ts` and `sandbox-windows-acl` forwards an existing fd 7 into the restricted child, refusing control with piped stdio.

Three upstream additions in the same neighborhood were restored. `disposeManagedProcesses` again awaits each control endpoint's `close` before clearing the set (upstream `562e7f364e`), which is what makes `channel.closed` true once disposal returns; the registration site already removed a closed endpoint, so every entry it awaits is one `destroy()` will still close. `win32-process` again hides the initial console — `STARTF_USESHOWWINDOW` and `SW_HIDE` in `abi.ts`, `wShowWindow` in the `STARTUPINFOW` encoder, and both `spawnPipedProcess` and `spawnJobProcess` flag sites — and `launchWindowsJob` passes `windowsHide: true`, which is why the comment there rejects `CREATE_NO_WINDOW`: a restricted token can fail DLL initialization without a console. `sandbox-windows-acl/tests/control.spec.ts` is upstream's file and spawns `win32-process/tests/fixtures/console-state.ts`, restored byte-identically.

**The control descriptor must be an overlapped pipe on Windows.** The merge replaced both `'overlapped'` stdio entries in `runnerStdio` with `'pipe'`. A synchronous pipe cannot carry a `net.Socket` endpoint on Windows: the child's first write, and that write's callback, are deferred until the far end reads, so a child that greets before reading never delivers its greeting and a child parked in `c.write(…)` never reaches `c.destroy()`. Restoring `'overlapped'` — the value upstream's own `ptc-runtime-node/tests/process.spec.ts` passes for descriptor 7 — turns `ptc-runtime-node/tests/runtime.spec.ts` from twenty timeouts into 26 passed | 1 skipped, and lets both lifecycle cases stay in `subprocess-local/tests/control.spec.ts` rather than an excluded file.

## Session deletion forgets through the workspace registry

`packages/workspace/workspace` exposes `registry.forgetSession(sessionId)`, so `session-deletion` calls it for the workspace leg of a deletion plan and advances that member to `done`. The consumer carries no compensation for an absent registry method: a missing `workspaceRegistry` marks the member `skipped` and the durable plan records that outcome.

## Subagent working-directory injection

The merged `SubagentRuntime` resolves every child's directory through `ctx.workingDirectory.ensure(parent, signal)`, so the service is part of its injection set. A composition that mounts the subagent runtime without `dsh-working-directory` leaves every start and every cold resume pending rather than failing loudly: the base bundle mounts it, and tests mount the shared `mountWorkingDirectoryFixture`.

## Workflow execution is upstream's PTC runtime

The fork ships `packages/workflow/workflow-worker-thread`, a `node:worker_threads` engine. Upstream retired that substrate: [workflow sandbox reuse](2026-09-13-workflow-ptc-sandbox-reuse.md) implements `WorkflowEngine` in `packages/workflow/workflow-ptc` over the shared Node `PtcRuntime` and rejects a second launcher, because worker termination cannot apply the Session's file policy or the managed process cleanup direct Node code already needs. The merge had taken neither side whole: `apps/cli/package.json`, `tsconfig.host.json`, `scripts/gen-doc-graphs.ts` and `packages/experimental/ralph-bundle/cordis.patch.yml` were upstream's and named `workflow-ptc`, while `packages/bundle/base/cordis.patch.yml`, the `standard`, `ptc` and `cordis` web-app presets and both model-facing consumers were the fork's and named `workflow-worker-thread`, so both engines were imported and only the fork's was mounted.

The engine is upstream's now. The base bundle mounts `@deepseek-ai/dsh-ptc-runtime-node` beside `@deepseek-ai/dsh-workflow-ptc`; the web-app bundle disables that host row and each preset mounts the engine inside the realm that already isolates `workflowEngine`; `tool-workflow` and `tool-ralph` compose their real-engine cases through `mountWorkflowRuntime` from `packages/workflow/workflow-ptc/tests/setup.ts`. The fork's package is retired with every entry point: the `./worker` export and its path alias, the tsconfig project reference, the CI native-lane and `processBoundTests` rows, the source-workflow and built-worker gate entries, the manifest dependencies, and the group, subsystem and composition-reference rows.

`packages/workflow/workflow-worker-thread/tests/integration.spec.ts` asserted `ctx.agents.get(agent.childId)` at `workflow/agent-start`. That is not the merged lifecycle's publication signal: `ctx.subagents.startActivation({ delivery: 'caller' })` resolves at admission, and the child becomes readable in the agents registry later. Upstream's replacement spec asserts the publication the engine actually owns — a `subagent/start` event observed before the workflow's own `agent-start` — and neither engine needed a change to satisfy it, because both emit `agent-start` only after `startChild` resolves.

## Settings namespaces come from the composition

Upstream replaced the settings provider seam: `SettingsForms` derives one namespace per active Loader entry from that entry's exported `Config` schema, so a plugin declares its section instead of calling `ctx.settings.register()`. The fork's consumers were migrated rather than the seam restored — `settings-controller` imports `SettingsForms`, fills `autoGenerate` from the presentation map, and declares `agent-preset/read-only` in `RemoteErrorDetailsMap`; `mcp-manager` declares a volatile `Config` dict and moves its declarative cross-check into an internal `config` waterfall listener gated to an active fiber, keeping the fork's write refusal and stored-section backstop.

## Session format v4 admission

The merge adopted `SESSION_FORMAT_VERSION = 4` and imported `packages/session/session-format-v3-to-v4`, but the fork's `packages/session/session-persistence-jsonl/src/format.ts` — which the merge kept whole — still admitted current-generation rows with `assertV3RowAdmission` and never ran `assertReleasedV4Relationships`. V3 admission requires a `system/message` source of `kind: 'plugin'`, while the merged `createSystemMessage` writes `kind: 'system-prompt'`, so the scanner refused every log the loop writes and every read-back path failed. The port re-applies upstream's three lines onto the fork's scanner: `KNOWN_SESSION_EVENT_TYPES` in the import block, `assertV4RowAdmission(decoded, KNOWN_SESSION_EVENT_TYPES)` in `consumeEventLine`, and `assertReleasedV4Relationships(artifact, KNOWN_SESSION_EVENT_TYPES)` in `finish()`, plus the dependency, project reference, and aggregate reference that name `dsh-session-format-v3-to-v4`.

## The archive instant is restored at its producer

Upstream's registry never carried an archive instant — `git log -S archivedSessionAts upstream/master` is empty and its `archivedSessionIds` is archive order alone. The merge took `packages/workspace/workspace/src/{index,spec}.ts` from upstream while keeping the fork's `workspace-controller` wire and Client layers, so 49 read sites under `packages/api` plus `ui-settings-archived` read a map with no producer; the two failing cases in that package's own host spec were the symptom. The fork's producer is restored additively on upstream's registry: `workspaceDomainState.archivedSessionAts` (`z.record(sessionId, z.string()).default({})`), stamped by `archiveSession` in the same durable write that drops the pin, and dropped by `unarchiveSession` and `forgetSession`. Upstream's archive verbs, archive-admission events, and pin set are untouched, and the domain version stays 2 because the field defaults for pre-field media.

## The gateway follows upstream; caller authority stays the fork's

Upstream reworked the Remote stream protocol across `packages/api/gateway` and `packages/api/remotes` together and at the same time replaced `dsh-client-connection`'s caller model with one operator Peer that every admitted request speaks for. The merge had taken the pair's tests and left its sources at the merge base, so the two planes agreed on RPC and disagreed on session and stream state: the client booted, the host created and persisted the live session, and the composer never unlocked. The pair is upstream's now, with the ten fork-only hunks inside it re-applied — the four extra Remote mounts (`sessionPins`, `mcpServers`, `mob`, `notes`) and the three forwarded events they need (`skills/change`, `mcp-servers/change`, `notes/material-settled`), their manifest dependencies and project references, the fake credentials owner's `readRecord`, the `socket` and `setHeader` members the authority stubs need, and `authorizeIndex(...) === 'serve'`.

The caller model stays the fork's. Connection keeps the paired-device authority, where a device cookie carries less than the loopback launch token — `isLocalOperatorRequest` is the gate the mobile routes use — so `HostConnectionHandle.admit(request)` returns the Peer of the caller's own class: the operator Peer for the launch-token credential, and that device's own Peer for a device cookie. Upstream's `admit` returns the operator Peer to every admitted request; adopting that would have promoted a paired device to the operator, so `ConnectionPeer` (`packages/client/connection/src/peer.ts`) is the one implementation — a scope owned by Connection, minted once for the operator and once per device. The RPC interceptor's fourth argument is the requesting caller's Peer, resolved where the TCP peer is still observable, so scoped delivery and the stream mux's peer-lifetime binding never cover a class the credential did not earn. Revoking a device disposes its Peer, which is what ends the streams that device already holds.

**The Client half takes upstream's handle and keeps the page-absent carrier.** Upstream's `ClientStreamHandle` primes the downlink at construction, which is what orders its `open` frame ahead of any `send()`; the same priming resolves the Connection when a stream method is called, so a missing transport throws at the call, and the first read of a retired namespace reports `Remote method <endpoint> is no longer mounted` before it awaits the carrier, so an unread stream never waits on a Host that is gone. Upstream resolves the mux socket against `document.baseURI` alone, which exists only inside a page; this fork's carrier also runs where no page exists, so `remoteStreamUrl` tries the transport's `streamBaseUrl`, then the document base, then `location.origin`, then `http://dsh.internal`.

**Boundary values are the Host's to reject.** `requireStrictInputs` refuses a descriptor without a strict codec when it is mounted, and the Host decodes every wire field — invocation identity, parameters, uplink items — through `codec.create().parse(value)` as `gateway/input-invalid`. The Client therefore forwards values verbatim and owns arity, Context adapters, Connection liveness, and descriptor strictness alone. A cancelled forwarded event is likewise the Host's to absorb: the Client withholds a reply once it has observed the Host's `cancel` frame, and a reply the Host no longer awaits is an idempotent no-op in `receiveRemoteEventResult`.

**RPC attachments are not framed.** Upstream carries a handler's binary attachments in a multipart response. This transport frames JSON alone, and no codec in this tree projects attachments, so `ConnectionRpcAttachment` exists in the handler contract while `fullResponse` refuses a result that carries one rather than answering with `null` placeholders. Binary payloads keep travelling through exact Fetch routes.

## Deliberate shelvings

**The Office line.** Upstream's Office client packages are not imported and no bundle mounts them; this fork ships its own plugin inventory page.

**Three unmounted upstream client packages.** `client-ui-cot-translation`, `client-ui-voice-input`, and `ui-plugin-manager` are shelved like the Office line: no bundle mounts them, and their slot seats exist only in upstream's client packages, so declaring the slots locally would leave dead registrations.

**Upstream's `session-inspector` and `inspector-profile`.** The developer inspection surface is shelved for the same reason: its grouped Chat presentation is written against upstream's conversation group engine — `ConversationGroupedView`, `GroupKey`, `GroupSnapshot`, `NodeReference`, `RenderEntry`, `snapshot.views.grouped('chat')`, `conversation/group-store.ts`, `ConversationBinding.openTurn`, and `ChatSnapshotBuilder.publish` — none of which exists in this fork's `ui-conversation` or `ui-chat`. Porting it would mean adopting upstream's conversation architecture into two UIs the fork owns outright, so the package, its `inspector-profile` bundle, that bundle's `OPTIONAL_BUNDLES` row, the client slot-catalog occupant, both tsconfig aggregates, the path aliases, the manifest dependency, and the composition-reference row are removed together. The inspector returns with upstream's group engine if that engine is ever adopted.

**Upstream's `tool-schedule`.** The merge first kept the fork's schedule plugin and ported upstream's two expectation specs onto the fork's `after`/`at`/`every` model. That shelving was reversed: the fork's model is retired whole and upstream's `ScheduleService` line is adopted — host package, `tool-schedule`, the `scheduleRemote` Remote contribution with its `schedule/changed` forwarded event, the client, and the specs. The reversal is recorded by the adopted [Host Schedule storage](2026-09-16-host-schedule-storage.md) decision and the [preset-scoped reminder tools](2026-09-24-preset-scoped-schedule-tools.md) decision; the fork's Session-log authority note is archived at [Durable scheduled reminders](../../archived/feature/2026-08-05-durable-web-schedule.md).

**The preset directory-opening surface.** The merged `AgentPreset` carries no trust and no path, because upstream replaced the fork's directory-discovering agent-presets package with a registry that declares presets inside `cordis.yml`; opening a user-authored preset directory therefore has no data source. The surface was removed end to end — both preset-opening Remote methods, the SettingsController `nativeOpen` field, `canOpenPath`, `AgentPresetDirectoryOpenValue`, the `agent-preset/read-only` error code, the connection fixture dispatch entries, the `ui-agent-preset` location affordance with its locales and CSS, and the cases that only covered it. Restore `agent-preset/read-only` if a Host-side `deletePreset` returns.

**Upstream's `remote-mock`.** The gateway's upstream client spec needs `@deepseek-ai/dsh-remote-mock`, a test-support package this merge never imported, and naming it as a `workspace:*` dependency makes `pnpm install` fail outright. The fork's `gateway.client.spec.ts` stays and the dependency is dropped; it runs on the spec's own fixtures, which assert the Client half's obligations — mounting, arity, adapters, liveness, descriptor strictness, carrier lifecycle, uplink framing — rather than a stand-in assembly.

**The runtime-invariant companions of packages taken from upstream.** Upstream retired the runtime-invariant plugin system, so every package this merge adopted from upstream lost the `./invariant` companion the fork had added to it: 29 companions across `core/{agent,agent-loop,scope,session,system-prompt,tools}`, `llm/{llm,llm-retry}`, `settings`, `workspace`, `jobs`, `compaction`, `interaction/*`, `credentials/*`, `goal/*`, `plan-mode`, `sandbox-policy`, `schedule`, `storage-domain`, `subagent/*`, `tool-todo`, `agent-presets`, `hook-protocol` and `time-context`. The packages the fork still owns keep theirs — 11 companions remain — and upstream's retirement is adopted rather than reversed, because restoring the rest would mean re-publishing a mechanism upstream removed wholesale. What that costs is the omission reason the fork's own gate requires: `verify-package-invariants` reads it from every package README, and the 145 upstream-adopted READMEs had none, so each now states what its package contributes and which service owns the relationship it does not check.

**The `plugin-manager` row in the base composition.** Upstream's base mounts `@deepseek-ai/dsh-plugin-manager`, guarded by `!ctx.get('profileContext')`. No bundle in this fork has ever mounted it — the fork's tip carries the same absence, so this is a composition choice rather than merge damage — and its consumers here are `packages/api/remotes` and `packages/host/plugin-inventory`, which reach it through `ctx.get` and degrade when no profile supplies it. Mounting it is therefore a product decision about what a default profile offers, not a convergence.

## What the whole-worktree acceptance found

`pnpm run build` (exit 0), `pnpm run test`, and `pnpm run check:all` left 424 failing unit cases across 59 files and 15 failing gates. Every unit failure was classified against `upstream/master`, the fork tip `6759bec009`, and the merge base `aa8262ec09`. All but five are host-bound — no Developer Mode, so every `symlink` setup dies with `EPERM`; no PowerShell 7; vitest's five-second default against suites that spawn dozens of processes — or recorded fixtures owed a macOS/Linux refresh. The five were this port's own damage, and each is repaired on upstream's side of the divergence:

- `vitest.config.ts` excluded the fork's pre-rename `packages/experimental/code-runtime-python` on win32 but not upstream's `packages/experimental/ptc-runtime-python`, whose backend refuses Windows in its constructor, so 294 cases upstream never schedules on this host ran and failed. Both spellings are excluded while both packages ship: the fork's older runtime is still composed by `snapshots/session/ptc-python-turn/cordis.yml`, so retiring it is a product decision rather than a merge repair.
- The three shipped-bundle specs still pinned the fork's opt-in HMR row, which `63587d6197` had already replaced with upstream's `dsh-hmr` row and each application overlay's `disabled: true` override. `packages/bundle/{base,sdk-app,acp-app}/tests` take upstream's assertions.
- `packages/client/ui-theme`'s scrollbar trio was byte-identical to the merge base while the merge adopted upstream's `ui-schedule` stylesheets, which rebind `--dsh-scrollbar-thumb-border`, `--dsh-scrollbar-track-margin`, and `--dsh-scrollbar-width`. `src/styles/scrollbar.css`, `tests/scrollbar-styles.client.spec.ts`, and `tests/stylesheet-scan.ts` come from upstream as one unit — the spec asserts the routing the CSS defines, so taking either alone is what failed.
- `packages/client/ui-tool/tests/tool-fixtures.client.ts` still logged the retired user-role tool-result envelope after the message model moved to upstream's tool-role `ToolResultMessage`. The Chat projection reads `message.content` and `message.isError` directly, so the fixture's `content[0]` was a `tool-result` block, `singleResultText` found no text, the terminal card model returned null, and the row lost its expand.
- The built-bundle sweep lacked upstream's `529434e1df`. Its Dockkit `.css` exemption was pinned to one stylesheet path, while the swept bundle reaches `@deepseek-ai/dsh-client-ui-primitives`' source stylesheet first through the launcher's tsconfig `paths`, so a legitimate refusal was reported as an unexpected baseline failure. The exemption admits any unknown-`.css`-extension refusal again.

Two gaps are recorded rather than repaired. Upstream's `packages/ssh/*` has no counterpart here: the port never imported it, nothing in this tree names it, and the merge base never had it, so no current path is broken — but the capability and upstream's matching win32 exclusion are absent together. And the present-open path dropped upstream's native file-application chooser (`packages/client/ui-open-in-app/src/client/*` with the `workspacePathApplications` Remote) when the fork's `present-open.ts` won that resolution; upstream's case for it went with its prerequisites, so the fork-side choice is self-consistent and is written down here rather than left implicit.

## Alternatives considered

- **Keep the fork's own settings provider seam.** Rejected: upstream derives namespaces from the Loader composition, which is also what makes a plugin's section appear without a registration call; keeping both would leave two authorities for one section.
- **Keep the V3-era session-format versions.** Rejected: the merged session family, session-format catalog, migrations, and web profile are v4 throughout, so pinning the JSONL backend at v3 would have required reverting `createSystemMessage`, the message-source vocabulary, and the imported edge.
- **Adapt upstream's tests to the fork's `win32-process` API instead of porting the missing accessor.** Rejected: `sandbox-windows-acl`'s failure-path spec is upstream's and exercises the same native layout the fork's eager bindings already materialize; a one-line accessor keeps both sides compiling without rewriting a spec.
- **Delete the job mirror instead of wiring it.** Rejected: `ui-jobs` renders over the mirror and the Web profile mounts it, so the deletion upstream performs would have removed a shipped header.
- **Admit every request as the operator.** Rejected: `admit` would then hand a paired device the operator Peer, and a device cookie is deliberately weaker than the launch token. The gateway's calls are adapted onto the fork's authority classes instead, and the property is pinned by a case that fails if a device is admitted as the operator.
- **Keep the fork's worker-thread workflow engine.** Rejected: upstream's [workflow sandbox reuse](2026-09-13-workflow-ptc-sandbox-reuse.md) already retired that execution substrate, its mounts, catalogs and consumers are upstream's, and keeping both engines would leave two authorities for one seam that the merged tree imported but only one of which it mounted.
- **Adopt upstream's `dsh-client-connection` whole.** Rejected for this merge: it would decide the fate of the fork's paired-device registry, which is the fork's own security surface and not a merge decision to make in passing. The gateway's five Connection call sites are adapted onto the fork's seam instead.

The Client spec needed no `@deepseek-ai/dsh-remote-mock`; see Deliberate shelvings.
- The web lane reaches its assertions. `apps/web/tests/archived-sessions-settings.e2e.ts` passes — the archived-settings row, the `Archived YYYY-MM-DD` instant, the restore flow and the confirmed recursive delete — and so does `startup-auto-selection.e2e.ts` (2/2). Two things had to land for that: the composer's Access seat reads the merged permission model (next bullet), and the isolated transcript preparer binds the V3→V4 edge to an empty child set — `prepareSessionSnapshotFixtureForComparison` now restores through `createSessionFormatCatalogWithChildren([])`, because the static catalog's header-only declaration refuses every historical body.
