# Agent Note: 素材详情头部与对话区重构

Status: implemented

[English](2026-09-22-notes-detail-rework.md) | 中文

## 问题

一次详情页走查发现四个可读性缺陷：来源条常开、与正文争抢注意力；操作行把状态字与五个按钮混排；模型回答引用正文时（如「Markdown（专有名词，通常不译）」这类）与素材自身内容无法区分；追问框悬在面板中部、对话内容松散居中。

## 决策

详情头部现在承载正文以外的一切：素材标题、状态标签、一个把来源记录（来源标签、类型、定位入口）折叠进发丝卡的「查看详情」开关，以及一个收拢行级操作的「⋯」菜单——复制、归档（已归档素材为取回）、删除。删除改走 ui-primitives `RiskConfirmation`（勾选确认才解锁提交），取代原先的一击即删。复制反馈不再翻转按钮文字，改为头部短暂出现的「已复制」提示。模板分区的标题文案改为「提示词」/ Prompt。

正文区只保留正文与草稿自身的生命周期控件——保存与分析放在编辑器下方的 `bodyFoot` 行，因为它们作用于正文本身、放在别处没有意义。分析是草稿的主操作，因此保留 primary 按钮样式放在明面上，而不是藏进菜单。

对话区拉伸填满面板剩余空间（`flex: 1; min-height: 0`)：内容行从顶部开始内部滚动，追问卡固定在底部，样式仿主会话输入框（22px 胶囊圆角、`--dsw-specific-input-major` 底、`--dsw-elevation-soft` 并把发丝描边重绑到 `--dsw-alias-border-l2`，发送控件内嵌）。用户行保持 `--dsw-specific-bubble` 气泡；AI 回答行是平面排版、正文上方加本地化的「回答」/ Answer 角色标签，使引用正文的回答绝不会被读成正文的一部分。追问输入框去掉自己的边框、融入卡片。

走查遗留的「标题行与正文卡首行重复」刻意保持现状：标题行与正文卡是同一段文本的两种呈现（一个为素材命名，一个是记录本身），隐藏正文首行会破坏详情页要展示的记录。

## 曾考虑的替代方案

- **来源卡用浮动 popover。** 否决：ui-primitives 没有点击式 popover 原语（HoverCard 仅悬停），头部下方的折叠卡以零裁剪与定位逻辑满足同一需求；卡内的「定位原文」按钮保留「本版不能跳转」的行内提示。
- **五个操作全部收进菜单。** 保存与分析否决：两者是草稿正文自身的生命周期，把草稿的主操作埋进菜单，对主流程的伤害大于对称性的收益。
- **左侧强调条代替角色标签。** 否决：2px 中性边框与发丝规则的中性边框约定冲突，显式的本地化角色标签在各语言下都无歧义。

## 后果

- `notes-detail.client.spec.tsx` 跟进新结构：折叠开关、复制/归档/取回的菜单流程、风险对话框的勾选确认与取消路径、菜单外点关闭；`MaterialDetail.tsx` 保持 100% 覆盖（包内 433 个测试全绿）。真机探针截图验证了草稿头部、展开的来源卡、菜单、删除确认框，以及带角色标签与底部固定追问卡的回答态对话区。
- `notes-refresh` 黄金文件的 diff 恰好是头部 chrome 的替换加回答角色标签。
- 无协议、store 或 model-visible 变更：新 chrome 调用的每个命令都早已存在。
