# Agent Note: 素材标题与行尾菜单

Status: implemented

[English](2026-09-22-notes-material-titles.md) | 中文

## 问题

素材行的标题是它的来源标签（如「对话中的选区」)，同一会话里的每一行读起来都一样；行尾的「对话」来源标签重复着行已不再需要的信息。读者无法给素材命名，而行上唯一的操作只有归档。

## 决策

素材记录携带可选的读者自设 `title`(`domain.ts` 的 `materialRecord`)：该字段在记录 schema 里默认 `null`，因此字段出现之前写下的文档仍能解析——notes 域的单文档布局在打开时拒绝版本戳不匹配、且没有兼容阶梯，所以该字段**不**升 `NOTES_DOMAIN_VERSION`，理由记在版本号的文档注释里。宿主侧新增 `Materials.rename(id, title | null)` 与 remote 端点 `materialRename`；标题是表现层元数据，因此已提交的素材也接受改名（与正文不同——正文归会话日志所有）。空白标题裁剪为 null，素材回到派生标题。

客户端的 `materialTitle()`(`src/client/title.ts`）决定行与详情头部显示什么：已存储的标题优先，否则取正文首个非空行、裁剪并按 40 个字形簇（`Intl.Segmenter`，截断不会切开 emoji）加省略号，无文本的截图回退到来源标签。行尾的来源标签移除；行尾改为两个控件——归档按钮与「⋯」菜单——坐在归档手柄确立的同一套流内 visibility 座位上，随行 hover 或 focus-within 显现。菜单（ui-primitives `Menu`,portal 渲染以免被列表列的滚动容器裁剪）打开由 `Modal`、`Input`、`Button` 组成的改名对话框——与工作区会话改名弹窗同形态，含 IME 组合保护。草稿为空白时保存不可用；没有单独的「恢复默认」入口，因为对话框拒绝的空白写入正是回到派生标题的操作——读者需要时再补。详情页头部（`data-notes-material-title`）显示同一个标题，来源区仍保留收集来源自身的标签。

## 曾考虑的替代方案

- **把 `NOTES_DOMAIN_VERSION` 升到 3。** 否决：单文档布局没有 `compatibleVersions` 路径（该阶梯只存在于 per-record 单元），升版本会让每个既有 notes 单元以 `version-mismatch` 打不开。可缺省的新增字段让旧文档可读、旧二进制前向兼容（zod 剥掉未知键）。
- **行内改名。** 否决：产品的改名惯例是弹窗加聚焦全选输入与 IME 安全的 Enter（工作区浏览器的会话改名）；在列表里发明第二种形态会漂移。
- **在宿主侧派生标题。** 否决：派生是对列表已携带数据的纯表现计算，Web 层拥有表现；存储派生副本还会让它在正文编辑后冻结。

## 后果

- 行读起来是标题而不是重复的来源标签；改名跨重启持久；已归档区与其取回行不变。
- 覆盖：`title.ts` 单元测试（首行、裁剪、40 字形簇上限、回退）、行菜单与对话框流程（Enter、IME 组合、空白禁用、取消、外点关闭）、宿主改名（裁剪、空白清除、已提交素材、未知 id)，以及一条证明旧格式记录可解析的域测试。`notes-refresh` Web 黄金文件的 diff 恰好是行标题与详情标题的变化；真机探针端到端改名并在宿主 store 中读到。
- 来源标签仍存在于记录与详情来源区；只有行不再重复它。
