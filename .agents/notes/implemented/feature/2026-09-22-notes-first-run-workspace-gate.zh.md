# Agent Note: 笔记面板的首启工作区门

Status: implemented

[English](2026-09-22-notes-first-run-workspace-gate.md) | 中文

## 问题

笔记面板在没有配置任何工作区时就亮出全部界面件——新建会话、历史、设置、刷新、浮窗——读者第一次点「新建会话」才收到 `workspace-missing`。首次启动的设置流程是一次拒绝，而不是一条引导。

## 决策

当设置节解析为没有工作区时，面板只挂载 `WorkspaceGate`：一张居中的卡片，一个文件夹图标、一行标题、一行提示，加上工作区目录字段。其余所有控件——整条导航栏、空状态的新建按钮、图片输入——都不进入组件树，因此读者够得着的任何东西都不会依赖一个尚不存在的工作区。门控条件精确等于已读设置节上的 `settings.workspace === null`：尚未读出或被拒绝的设置读取不算门，因为那种状态有自己的加载与失败提示，不能伪装成首次启动。

目录字段就是设置卡本来在编辑的那个，提取为 `WorkspaceField`（输入框加选择目录，在部署不提供原生选择器时回落到基于宿主目录列表的浏览器），让门与卡共用同一条写入路径：选择或选定目录是有意为之的值，立即通过 `notes/settingsUpdate` 保存；重读的设置节点名目录之后，面板随之开放。在设置卡里清空目录会让面板回到门——这是同一个条件在起作用，而不是第二套机制。

## 备选方案

- **把"设置尚未作答"也当作门。** 否决：这会让每个部署在每次全新挂载时都闪一次门，而设置读取被拒绝（没有挂载 provider）时，读者会被困在一个保存落不了地的选择器后面；那里正确的答案是正常内容加上失败提示。
- **用模态框或应用级引导界面。** 否决：`OnboardingSurface` 会 portal 到整个应用之上并让根节点 inert，比需求重——门只属于笔记面板，它显示期间应用的其余部分必须保持可用。
- **在门里复制一份浏览流程。** 否决：原生选择优先、列表浏览器兜底的流程与设置卡完全相同，复制两份迟早漂移；`WorkspaceField` 是共享组件，`WorkspaceField.module.css` 拥有卡片现在 compose 的字段与浏览器样式。

## 影响

- `notes-panel.client.spec.tsx` 新增 `first-run workspace gate` 测试块：门会隐藏其余所有控件且不会启动会话；原生选择保存 `{ workspace }` 并解除门控；没有原生选择器的部署浏览宿主目录列表并选定某一层，效果相同（包内 436 个测试通过）。
- `NotesSettingsCard.tsx` 把它私有的 `DirectoryBrowser` 与浏览状态移交 `WorkspaceField.tsx`；它的 CSS 模块从共享模块 compose `field`，卡片的数据属性与提交行为不变。
- 两份 README 中"没有首启引导界面"的已知限制条目被改写：门就是引导界面，而 `workspace-missing` 仍然是在面板之外发起启动时的 wire 拒绝。
