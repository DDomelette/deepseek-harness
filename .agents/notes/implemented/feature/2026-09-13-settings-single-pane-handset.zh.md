# Agent Note: 手机上的单窗格设置面板

Status: implemented

[English](2026-09-13-settings-single-pane-handset.md) | 中文

## 问题

手机通过 [LAN Web 服务](../architecture/2026-09-11-lan-web-serving.zh.md)访问 Web UI，但设置外壳一直是双列面板：188px 的分区导航栏与内容列并排放在固定 800px 的面板里。面板的 `max-width: calc(100vw - 48px)` 会把整个界面压缩到约 390px 手机上的 340px 左右，内容列只剩约 150px——窄到分区文案逐字换行，「外观」「语言」「字号大小」等控件因此无法使用。

## 决策

在 `packages/client/ui-settings-general/src/client/pane.ts` 的 `SETTINGS_PANE_BREAKPOINT = 768` 以下，面板铺满视口并一次只显示一个窗格：先显示分区列表，再单独显示所选分区。`SettingsPanel` 把该选择发布为 `data-pane`（未选分区时为 `list`，之后为 `detail`），样式表则依据媒体查询加该属性决定窗格切换、合并后的顶栏与 40px 触控目标。二级窗格的内容头部增加返回控件，旁边是分区名，因此两个窗格不需要各自的导航；Escape 先返回列表，再关闭对话框。

窗格切换是对一个已发布属性的媒体查询，而不是视口订阅：渲染代码不读取任何实时事实，只有 Escape 处理函数通过 `isSinglePaneViewport()` 读取视口宽度。断点与 ui-layout 的 `SIDEBAR_OVERLAY` 一致；客户端功能包之间不共享运行时的值，因此本包保留自己的一份。

在手机布局中，导航列与内容列不再生成盒子（`display: contents`），其子元素成为面板的网格项：第一行是 60px 顶栏，承载外壳标题，或返回控件与分区名，并与共用的关闭控件同排；第二行承载当前选择对应的窗格。因此每个窗格都只有一个关闭控件，位置仍在双列面板原本放置它的右上角。

覆盖：`apps/web/tests/settings-mobile.e2e.ts` 驱动 390×844 的页面——列表窗格铺满手机且分区内容不在屏上，点击某行后该分区独占窗格并显示分区名与返回控件，返回后回到列表且对话框不关闭，页面没有横向溢出——随后在同一页面以 1680px 重跑，锁定未变的双列布局，且该布局不提供返回控件。

## 曾考虑的替代方案

- **在组件中订阅视口。** 否决：业务组件不承载订阅机制，而当前显示哪个窗格可以由已发布的选择用 CSS 表达。
- **在列表窗格内再加一个关闭控件。** 否决：对话框会出现两个可访问名称相同的控件；把两个头部合并成一条顶栏可以只保留一个。
- **接近全屏、但保留可点击背板的卡片。** 否决：分区内容需要手机的全部视口，因此面板保持全高，遮罩不参与交互。

## 后果

- 双列布局不受影响：所有新规则都在 `@media (max-width: 767px)` 内，或以 `data-pane` 为条件，桌面设置场景回放不变。
- 每个窗格在固定顶栏之下各自滚动。
- 设置外壳之外的次要界面保持桌面布局。
