# Agent Note: Session 操作标识与可选反馈

Status: implemented

[English](2026-10-24-session-action-identity-and-feedback.md) | 中文

## Problem

Web 命令 UI 通过定义标识识别第一方命令。反馈或导出的生产方若没有此标识，命令仍可执行，但会失去本地化的第一方呈现。Session 页头还需要让反馈操作随反馈插件的生命周期变化，同时不能要求启用反馈插件才能使用 Session 导出。

## Decision

反馈和导出的生产方将包名声明为带品牌类型的 `CommandDefinitionId`。名称仍按[命令注册表](../feature/2026-07-19-plugin-command-registration.zh.md)的规则选择命令执行与作用域覆盖；定义标识选择第一方客户端呈现。

Session 导出插件通过 Cordis 注入观察可选的 `feedbackUi` 服务，并通过稳定的可观察源发布可用性。框架将该源绑定为页头的 hook。菜单仅在服务可用时提供反馈操作；回调再次读取服务，因为插件可能在渲染与点击之间卸载。打开反馈会关闭菜单并打开已有的 Session 草稿，不会记录反馈或启动下载。导出始终独立可用。

## Alternatives considered

**通过名称或描述识别第一方命令。** 作用域插件可以复用这两类值。定义标识保留生产方身份，无须解释展示文案。

**要求反馈插件存在后才激活 Session 导出。** 反馈是可选功能，缺少反馈插件不能移除独立的下载操作。

**在菜单回调中缓存反馈服务。** 捕获的服务可能比其插件存活更久。在操作发生时读取 `ctx.get('feedbackUi')`，可避免调用已退役的界面。

## Consequences

命令生产方拥有稳定标识，反馈插件拥有弹窗和 Session 状态。导出插件只拥有可选菜单贡献及其可用性观察。这会增加对反馈服务声明的仅类型开发依赖，不会导入其他功能插件的运行时实现。

Loader 测试验证生产方标识。页头与插件测试覆盖可用性变化、卸载、重新加载、菜单关闭及下载独立性。浏览器反馈场景验证关闭草稿不会记录任何反馈，提交则恰好记录请求的 Session 反馈。
