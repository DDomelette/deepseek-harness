# Agent Note: 笔记设置卡的保存时机与打磨

Status: implemented

[English](2026-09-21-notes-settings-card-polish.md) | 中文

## 问题

一次走查发现笔记设置卡（`NotesSettingsCard.tsx`）的四类缺陷：一个弹窗里三种保存心智（策略选项点击即写、保存目录要显式按钮、保存模型又要另一个按钮）、只读的 autoSend 标记以无上下文的裸文本呈现、DirectoryBrowser 文档注释里两处乱码 `鈥?`、以及 PR #60 在设置卡之外已收敛的手写按钮配方在这里还有第二份拷贝。

## 决策

整卡统一为一种保存模型，与宿主设置界面的惯例一致（DeepSeekModelsEditor 的文本字段在 blur 时提交）:**控件在值确定的那一刻保存**。策略选项本就如此；模型路由与推理等级的下拉现在选择即写；目录字段是自由文本，在 blur 或 Enter 时提交（绝不按键逐字保存），提交前裁掉首尾空白，裁剪后为空的值按取消设置写入——与被删除的按钮写的东西相同。通过原生选择器或卡内浏览器选中的目录在选中即存，因为选中本身就是决定。功能编辑器是唯一例外、保留显式保存：它从两个字段铸造一整条列表项，保存按钮改用 primary 变体，让提交点读起来就是提交点。

autoSend 标记改为保存控件旁的 quiet `Tag`，不再是裸文本。乱码修正为破折号。卡内其余按钮（策略选项、浏览、目录浏览器的行操作、新增功能）全部改用 ui-primitives `Button`(`sm`；默认 `outline`，选中态策略与功能保存用 `primary`)，卡内字号全部归入 `--dsw-font-*` 阶梯；`settings.saveWorkspace` 与 `settings.saveModel` 两个键从字典中移除。

走查提到的工具按钮标签断点问题由 #56 承担（它在那里把标签断点对齐到 559px)；本分支刻意不重复这个改动。

## 曾考虑的替代方案

- **到处保留显式保存按钮。** 否决：宿主自己的设置就是确定即写，一个弹窗三种心智正是要修的缺陷；功能编辑器的双字段铸造是唯一不是单个控件决定的写入。
- **保存前校验目录存在性。** 判为超范围：宿主的 schema 接受任意字符串，卡内浏览器选出的路径本就证明了存在性；手输路径在宿主第一次用不到它时会大声报错。裁剪空白是卡片自己拥有的唯一校验。
- **功能编辑器也在 blur 时自动保存。** 否决：新增功能的 id 在保存时铸造，blur 提交会把输入到一半的字段变成正式条目；primary 样式的显式保存就是提交点的标记。

## 后果

- `notes-settings.client.spec.tsx` 改为新时机：blur/Enter 提交、空白裁剪、未变不写、模型与等级即选即存、目录选取即存；`NotesSettingsCard.tsx` 保持 100% 覆盖（包内 403 个测试全绿）。
- 断点一项由 #56 回答；`notes-refresh` e2e 不打开设置卡，黄金文件无变化。
- 无 remote 协议或 model-visible 变更：到达 `settingsUpdate` 的 patch 不变，只有时机前移。
