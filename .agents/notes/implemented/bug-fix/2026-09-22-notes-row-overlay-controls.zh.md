# Agent Note: 行尾控件悬浮覆盖在卡片右缘

Status: implemented

[English](2026-09-22-notes-row-overlay-controls.md) | 中文

## 问题

[行手柄修复](2026-09-21-notes-row-handle-and-title.zh.md)引入的流内 visibility 座位始终预留行尾控件的宽度——两个控件（归档 + 「⋯」菜单）约 110px——因此即便控件没显示，素材行标题也提前截断（实测：242px 列宽下标题只剩约 40px)。产品侧给了手动 P 图的决定：标题与预览在静止时占满卡片全宽，悬停或聚焦时控件悬浮覆盖在卡片右缘、允许遮住一部分内容。

## 决策

座位取消（`MaterialList.module.css`)：行恢复 `position: relative`，两个控件收进一个绝对定位的 `.handles` 包裹层，位于卡片右缘、垂直居中。包裹层带不透明的 `--dsw-alias-bg-layer-1` 底色与少量左内边距，控件压在文字上仍可读；包裹层本身不吃指针事件，只有按钮吃（`.handles button`)，点在底衬上穿透到行的选择。显现仍是 `.row:hover` / `.row:focus-within` 加共享的 `:focus-visible` 焦点框；绝对定位不移动布局，出现依旧无抖动。drop 指示线、拖拽、窄档 chip 收起都不动。

e2e 暴露了一个座位时代被掩盖的真实碰撞：最窄卡片下可见的悬浮归档按钮延伸到了行按钮的水平中心——Playwright（以及手快的读者）点那里是想选中。底衬的点击穿透覆盖了内边距区；按钮自身仍是真实目标；`notes-refresh.e2e.ts` 改为点击行的文字端——读者选中行时真正做的手势。

## 曾考虑的替代方案

- **只保留「⋯」的固定宽度座位，归档按钮单独悬浮。** 否决：一半预留一半悬浮读起来是两套布局，而且单是「⋯」也为一个低频控件常驻约 36px。
- **控件下加左侧渐隐遮罩**（输入框的渐隐带做法）。判为不需要：按钮是自带边框的实心 chip，而行很短——它们盖住的文字本来就已经截断。

## 后果

- 真机探针实测：静止时内容区占满卡片（减内边距），标题约 191px（座位时代约 40px)；悬停时几何完全一致（零抖动），控件以不透明底色显现在卡片右缘内；键盘聚焦不靠指针也能显现控件。第二个探针验证底衬点击穿透选中行、Archive 按钮照常归档。
- [行手柄 note](2026-09-21-notes-row-handle-and-title.zh.md) 的流内座位决策被本条取代；其键盘显现与焦点框决策不变。
- 底衬部分被[让位跟进](2026-09-22-notes-row-hover-yield.zh.md)取代：底衬与其点击穿透规则移除——控件在卡片右端流内展开，文本为其让位。
- 包内 433 个测试原样全绿；`notes-refresh` 黄金文件不变（静止时悬浮层隐藏，ARIA 看不到它）。
